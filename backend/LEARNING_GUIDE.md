# Learning guide: understand this backend instead of treating it as a black box

This backend is a starting implementation, not a replacement for understanding the code. Keep the app running locally and inspect one request at a time.

## Read files in this order

1. `app/main.py` — application creation, middleware, router registration, lifespan and health checks.
2. `app/core/config.py` — environment variables, Pydantic Settings, defaults and secret configuration.
3. `app/core/database.py` — SQLAlchemy engine, session factory and per-request session dependency.
4. `app/models.py` — relational tables, keys, relationships, cascades and JSON fields.
5. `app/schemas.py` — request validation and response contracts. Compare schemas with database models.
6. `app/core/security.py` — development-only identity and Firebase ID-token verification.
7. `app/routes/users.py` — a small CRUD example with ownership and profile validation.
8. `app/routes/documents.py` and `app/services/document_service.py` — file validation, storage, text extraction, chunking and indexing.
9. `app/services/retrieval_service.py` and `app/routes/academic.py` — retrieval, source passages, prompts, citations and chat history.
10. `app/services/resume_service.py` and `app/routes/resumes.py` — the ATS_Resume_Template_2026-specific section rubric, PDF layout checks, GenAI semantic assessments, evidence validation and separate JD-alignment report. Read `reference/ATS_Resume_Template_2026.pdf` alongside this code.
11. `app/routes/study_plans.py` — constraints, scheduling algorithm and task state.
12. `app/routes/interviews.py` — persisted interview turns, AI evaluation and session lifecycle.
13. `app/routes/progress.py` and `app/routes/analytics.py` — ordinary data capture and aggregation.
14. `migrations/versions/0001_initial.py` — database schema history.

## How a typical request flows

`HTTP request → FastAPI route → input schema validation → authentication dependency → database session → service logic → database commit → response schema → JSON response`

The order can vary when the route does not need every component, but these are the main responsibilities.

## Recommended learning checkpoints

### Checkpoint A — no AI, no upload
- Run `GET /health` and `GET /health/ready`.
- Call `GET /api/v1/users/me` in local development mode.
- Update your profile with `PATCH /api/v1/users/me`.
- Explain why `get_current_user` returns a database `User`, while Firebase handles sign-in.

### Checkpoint B — persistence
- Create a project using `POST /api/v1/progress/projects`.
- Restart the backend and confirm the record remains.
- Inspect the record in PostgreSQL.
- Explain the difference between the SQLAlchemy engine and session.

### Checkpoint C — files
- Upload a small text-based PDF using `POST /api/v1/documents`.
- Inspect its metadata and download it.
- Upload the same file as a different development user and verify it is not visible to the first user.
- Explain why stored filenames are generated by the server rather than copied from the user's filename.

### Checkpoint D — AI
- Add a Gemini key only after understanding `.env` and Git ignores.
- Upload a syllabus, ask a question, and inspect citations.
- Test a question that is not answered in the supplied material.
- Read the retrieval code before changing prompts or models.

### Checkpoint E — template-based resume analysis
- Upload a real text-based resume PDF using document type `resume`.
- Call `POST /api/v1/resumes/analyze` with `job_description: null` and inspect all eight content-section scores plus the PDF-format score (whose individual check maxima add up to exactly 20 points).
- Run it again with one JD and confirm the template score stays the same while `job_description_alignment` contains a separate JD-alignment report.
- Check that positive evidence quotes are verbatim excerpts from the uploaded resume, including JD evidence and that no unsupported metrics are suggested as facts.
- Compare the visual PDF with `reference/ATS_Resume_Template_2026.pdf`; the automatic layout checks are heuristics, not a visual-diff engine.

### Checkpoint F — study planning
- Create a plan with a small number of topics and a short deadline.
- Observe `overloaded` and `unscheduled_minutes` when there is not enough time.
- Mark a task complete and inspect the analytics endpoint.

### Checkpoint G — interviews and analytics
- Start a text mock interview, submit an answer, and inspect its stored turns/evaluation.
- Add a project and a DSA record.
- Check that analytics come from persisted data rather than hardcoded dashboard values.

## Before you extend a feature

1. Write down the required behavior and edge cases.
2. Find the relevant request schema, route, service and model.
3. Implement one small change yourself.
4. Add a test that would have failed before the change.
5. Run `python -m pytest -q` and test the endpoint in `/docs`.
6. Explain your change and the reason behind it in your own words.

## Important architecture trade-offs

- The local development auth mode is intentionally simple but unsecure for public use. Firebase verification is the production path.
- The first RAG version stores vectors as JSON and ranks them in Python to avoid a PostgreSQL extension install during the initial learning stage. This is not suitable for a large document collection; migrate to pgvector before scaling.
- PDF processing runs in the request worker and is appropriate for small files. A durable background queue is a future reliability improvement for larger workloads.
- Scanned PDFs, OCR, voice-based interviews and autonomous job discovery are outside the current approved scope.
- Resume scores are calculated against the included ATS_Resume_Template_2026-specific rubric and PDF-format checks. They are not employer ATS scores or hiring predictions. JD alignment is separate from the template score.
- The PDF layout checks use PyMuPDF geometry heuristics. They can flag common format issues but cannot guarantee how every ATS parser will interpret a resume.
- Resume analysis sends extracted resume text and an optional job description to the configured Gemini API. Review the provider's data-handling terms and avoid sending sensitive information without appropriate consent.
